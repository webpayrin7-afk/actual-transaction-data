# 집랩 UI 정책 2.0

2026-09-22 · 기존 정책을 대체하는 신규 설계안 · 코드 적용 전

## 1. 목적과 적용 범위

집랩은 가격·거래·주거비·지역·생활 정보를 비교하는 데이터 서비스다. 핵심 정보는 빠르게 파악되고, 반복 데이터는 조용하고 정확하게 비교되어야 한다. 동일한 정보 역할에는 동일한 스타일을 적용한다. 기존 정책 및 이전 대화의 초안과 충돌하면 본 문서를 새 기준으로 사용한다. 기존 문서를 실제 삭제하거나 사이트 코드를 변경한 것은 아니다.

전역 적용: 폰트, 정보 위계, 색, 여백, 표면, 버튼, 입력, 상태, 접근성. 페이지별 구성: 상세는 비교와 읽기, 검색은 입력과 결과, 시장 홈은 핵심 요약, 지도는 지도 탐색에 맞게 배치한다. 모든 페이지를 동일한 카드 배열로 만들지 않는다.

설계 결정: 지나치게 조밀한 금융 단말형과 큰 카드가 반복되는 홍보 페이지형 대신, 본문 15px·표 14px를 기반으로 대표값만 강조하는 정보 중심 UI를 채택한다. 모바일 가독성을 우선하고 데스크톱에서는 읽기 폭과 비교 배치를 조정한다.

## 2. 확인 근거와 한계

사용자 제공 IMG_8410~8417 모바일 캡처 및 lhr.life 잠실엘스 페이지의 실제 DOM/computed style을 확인했다. 실측 브라우저 뷰포트는 1363×936 CSS px. 모바일 CSS 실측은 하지 않았으며 모바일 배치는 캡처를 근거로 설계했다. 다른 페이지와 모든 탭을 점검한 것은 아니다.

지정 font-family는 실제 한글 글리프의 렌더링 서체를 보장하지 않는다. 다만 제목과 본문에 다른 폰트 스택이 지정된 것은 확인했다. 관리비의 문제는 제목 크기가 아니라 반복 금액의 역할별 규격 차이와 강도다. 이전 캡처 분석에서 두 상세보기 버튼 색상이 다르다고 했으나 현재 페이지 실측에서는 같아 정정한다.

관리비 산정근거에는 기준월 2026년 7월, 선택 면적, 산식, 출처, 여름 2개월 평균이 이미 존재한다. 새 정책은 이 정보를 새로 만들기보다 핵심 조건을 요약 옆에 노출한다.

학교 탭 선택 후 “This page couldn’t load” 화면이 관찰됐고 한 번 새로고침 후 본문이 복구됐다. 학교 기능 결함 또는 특정 원인으로 단정하지 않는다. 별도 재현 점검 대상이다. 사용자 확인에 따라 네이버 지도 미표시는 인증 문제이므로 이번 UI 진단·개선 범위에서 제외한다.

## 3. 타이포그래피

본문과 제목 모두 Noto Sans KR → system-ui → sans-serif 단일 스택. 로고는 별도 그래픽 자산으로 유지한다. 기존 제목용 Outfit 스택은 UI 텍스트에서 제외한다. 폰트 굵기는 400/500/600/700 네 가지. 일반 자간 0, 제목만 -0.02em. 숫자는 tabular-nums, 금액/단위는 필요한 범위에서 한 묶음으로 유지한다.

표는 모바일 / PC의 크기·행간이며 단위는 CSS px. 구현은 rem을 사용하고 사용자 글자 확대를 허용한다. PC 기준은 1024px 이상, 768~1023px는 모바일 크기를 유지한다.

|---|---|---|---|---|
| page-title | 24/32 | 28/36 | 700 | 단지명·학교명·페이지명 |
| section-title | 18/26 | 20/28 | 700 | 거래내역·관리비·지역비교 |
| subsection-title | 16/24 | 16/24 | 600 | 관리비 구성·가격 비교 |
| hero-value | 28/36 | 32/40 | 700 | 페이지 최상단의 단일 대표 지표, 선택적 |
| summary-value | 20/28 | 24/32 | 600 | 최근 가격·관리비 요약·계산 결과 |
| compact-value | 18/26 | 18/26 | 600 | 여러 개가 반복되는 시설 수 |
| list-title | 16/24 | 16/24 | 600 | 거래금액·단지/학교 목록명 |

큰 수치를 모든 섹션에 배치하지 않는다. 반복 표의 값은 15px, 요약은 20px, 페이지의 단일 대표값만 28px다. 현재 단지 상세는 시세 요약의 매매/전세를 20px로 쓰고 별도의 28px 가격을 중복 추가하지 않는다. 비교값은 동일 규격이며 선택 대상을 강조할 때 크기를 바꾸지 않는다.

라벨을 작고 흐리게 줄이는 방법으로 위계를 만들지 않는다. 일반 콘텐츠 최소 14px, 보조 설명 최소 13px. 사용자 글자 확대 시 고정 높이를 풀어 내용이 늘어날 수 있어야 한다.

로고 색을 변경하는 작업은 본 정책에 포함하지 않는다. 사이트 UI의 행동색은 위의 한 가지 청록으로 통일한다. 일반 금액은 primary, 변화량에만 상승/하락색. “최고가 대비 -10.1%”는 down으로 표시한다. 가격 하락이 사용자에게 나쁜 일이라는 의미를 넣지 않는다. 청록은 클릭 가능성뿐 아니라 현재 비교 대상에도 사용하므로 비교 대상은 ‘선택 단지’ 등 구조적으로 식별한다. 링크는 밑줄·화살표·버튼 형태로 동작을 구분한다.

차트 계열: 매매 #087F83, 전세 #C2410C(가격 잉크와 동일), 거래량 #0F766E(보조 막대는 옅게 처리). 차트 계열색은 변화량 색상과 별도 토큰이다. 색 외에 범례명·선/막대 형태를 함께 사용한다.

상권 범주: 식음 #C2410C, 쇼핑 #0369A1, 생활서비스 #475569, 교육 #7C3AED, 여가체육 #15803D, 의료건강 #BE185D. 지도·아이콘·차트에 같은 매핑을 사용한다. pastel 배경은 색상 토큰의 연한 변형으로 지정하고 텍스트는 본문색을 유지한다. 순위 막대는 비교 목적일 때 단색을 기본으로 하며 범주 구분이 필요할 때만 범주색을 사용한다.

구현 검증 목표: 일반 텍스트 대비 4.5:1, 큰 텍스트 및 필수 컨트롤/그래픽 3:1. 장식 구분선과 상호작용 경계선을 같은 토큰으로 취급하지 않는다. 실제 배경·투명도가 반영된 조합을 측정한다.

## 5. 레이아웃·여백·표면

전역 여백 단위: 4,8,12,16,24,32,48. 별도 규격으로 카드 padding 20은 쓰지 않는다.

| 위치 | 모바일 <768 | 태블릿 768~1023 | PC ≥1024 |
|---|---|---|---|
| 페이지 좌우 | 16 | 24 | 32 |
| 상세 본문 최대 폭 | 가용 폭 | 가용 폭 | 1120 |
| 독립 카드 사이 | 24 | 24 | 32 |
| 카드 내부 | 16 | 24 | 24 |
| 페이지 제목 → 본문 묶음 | 24 | 24 | 32 |
| 제목 → 기준/설명 | 4 | 4 | 4 |
| 제목 묶음 → 본문 | 16 | 16 | 24 |
| 내부 묶음 사이 | 24 | 24 | 24 |
| 소제목 → 내용 | 12 | 12 | 12 |
| 라벨 → 값 | 4~8 | 4~8 | 4~8 |
| 컨트롤 사이 | 8 | 8 | 8 |
| 본문 → 하단 동작 | 16 | 16 | 16 |

최대 폭은 바깥 상세 컨테이너 기준이다. 상단 단지정보·차트·카드의 좌우 기준선을 동일하게 맞춘다. PC에서 카드 외곽이 넓더라도 좁은 폼과 라벨/값은 내부 최대 640px 범위에 두어 라벨과 값 사이가 수백 px 비지 않게 한다. 관리비·계산기 두 정보 묶음은 여유 폭에서 내부 2열로 배치할 수 있으나 비교 순서는 유지한다. 시장 대시보드는 최대1280, 지도는 전체 폭 등 페이지 유형별 예외를 명시한다.

카드 radius12, 버튼/입력8, 팝오버12, 바텀시트 상단20, 배지는 pill. 기본 카드에 그림자를 넣지 않는다. 경계는 1px border/subtle. 떠 있는 팝오버만 그림자를 사용한다. 바깥 카드 안의 목록을 다시 둥근 카드로 감싸지 않고 행 구분선을 우선한다. 주변 공급처럼 독립 클릭 대상인 항목 카드는 예외다.

일반 정보행 min-height44, 비교표 행44, 두 줄 거래행 min-height64. 내용이 길면 높이가 늘어난다. 셀 좌우12, 상하10~12를 적용하되 최소 높이와 중복으로 과도한 여백을 만들지 않는다. 제목을 제외한 단순 라벨/값은 좌측 라벨·우측 수치. 숫자 열 우측 정렬, 날짜 표기는 일관되게 한다.

## 6. 공통 컨트롤·탐색

기본 버튼 min-height44, 입력48, 주요 입력 검색48. 모든 터치 영역44×44. 아이콘은16 또는20이고 시각 크기와 터치 영역을 구분한다. 정보 아이콘13px 크기를 터치 영역으로 그대로 쓰지 않는다. focus-visible은 2px brand outline, offset2. disabled는 흐리게 하되 상태를 속성과 문구로도 구분한다.

Primary: 검색 실행·저장 등 우선 동작, 청록 배경/흰 글자. Secondary: 상세보기·비교 진입, 흰 배경/청록 글자/컨트롤 경계. Tertiary: 근거 보기·초기화, 텍스트형. 버튼 폰트14/20·500, primary/활성600. 페이지에 filled 탐색 버튼을 반복하지 않는다. 거래 내역 자세히 보기와 지역 순위 보기는 동일 Secondary.

페이지 이동/섹션 이동은 밑줄 탭, 한 영역의 보기 모드 선택은 segmented control, 면적/기간 등 조건은 필터로 구분한다. 각 유형 안에서 규격을 통일한다. 선택 시 글자 크기나 버튼 폭이 바뀌지 않게 한다. 모바일에서 제목 옆 필터가 좁아지면 필터를 다음 행으로 내린다. 전체 메뉴를 축소해 한 줄에 강제로 넣지 않는다.

페이지 상단은 PageHeader로 뒤로가기44, 제목, 보조설명 규격을 통일한다. 스크롤 후 압축 헤더가 필요한 경우 기존 헤더와 동시에 중복 점유하지 않고 한 레벨로 전환한다. 단지명16/24·600, 면적 선택14/20. 섹션 이동바와 겹칠 경우 합계 높이와 스크롤 오프셋을 공통 관리한다. 애니메이션120~180ms, reduced-motion에서는 제거한다.

모달/바텀시트: 제목18/26·700, 본문15/24, 옵션44 이상, 선택표시와 텍스트 동시 제공. 초점 이동·복귀, Escape 닫기, 배경 스크롤 제어, 하단 safe-area 대응. 예외적인 소형 폰트를 사용하지 않는다.

| 주변 생활 | 탭44, 기준13 한 번. 지도260 모바일/360 PC. 시설 수18, 시설명13, 아이콘20/박스32, 3열 기본 |
| 상권 구성 | 개별 막대+비율14를 기본. 같은 정보를 반복하는 누적 막대 제거. 막대에 같은 스케일 적용 |
| 주변 공급 | 이름16·600, 보조13, 입주일14·500, 링크14. 배지는 줄바꿈 허용 |
| 관리비 | 최근 예상액20/24·600. 기준월·선택 면적13을 요약 아래 노출. 평균/구성 라벨14, 금액15·600. 내부 제목16 |

관리비의 “최근 12개월 평균”은 실제 데이터가 12개월 미만이면 “최근 N개월 평균”으로 표기한다. 현재 데이터가 실제로 몇 개월인지 확인하기 전 N을 임의로 넣지 않는다. 여름 2개월 평균처럼 비교 해석에 중요한 범위는 근거 패널 안에만 숨기지 않는다. 반올림 때문에 합계가 맞지 않을 수 있으면 안내를 제공하되 실제 산식 확인 후 문구를 결정한다.

차트 툴팁은 화면 가장자리에서 위치 전환, max-width min(280px, viewport-32px). 수치가 잘리지 않게 하고 hover 전용으로 만들지 않는다. 슬라이더 시각 핸들은16~20, 터치 영역44. 선/범례 이름으로 구분하며 선택 데이터의 텍스트 접근 경로를 제공한다. 전체 기간에 점을 과도하게 표시하지 않는다.

## 8. 로딩·빈 상태·오류·출처

로딩은 기존 공간에 스켈레톤/진행 문구, 자료 없음은 ‘자료 없음’과 이유/다른 조건, 실패는 오류와 재시도. 자료 없음과 실제0을 구분한다. 부가 섹션 실패가 상세 전체를 대체하지 않도록 섹션별 오류 경계를 둔다. 정상 데이터가 있는 다른 섹션은 유지한다.

출처/날짜/범위는13px·secondary. 설명을 지나치게 흐리게 처리하지 않는다. 섹션 공통 조건은 한 번, 개별 값이 다른 조건을 가질 때 해당 값 옆에 별도 표기한다.

하단 고정 요소는 safe-area를 반영하고 마지막 콘텐츠가 가려지지 않게 한다. 스크린샷의 Safari 주소창 및 운영체제 영역을 사이트 여백으로 계산하지 않는다.

## 9. 구현과 수용 기준

단일 토큰 파일과 공통 역할 컴포넌트를 사용한다: PageHeader, Section, SectionHeader, Subsection, Metric, DataRow, DataTable, Control, SourceNote, AsyncState. 실제 이름은 저장소 구조를 따른다. 페이지별 임의 font-size/색을 허용하지 않고 의미가 다른 예외만 문서화한다. 기존 정책 클래스는 사용처를 매핑·치환한 후 제거한다. 레거시와 신규 토큰이 같은 역할로 병존하지 않게 한다.

현 단지상세 작업 브랜치에서 진행. 신규 정책 정의를 먼저 문서화하고 잠실엘스, 긴 단지명, 자료 없는 단지로 샘플 적용. DB 적재·재스캔·수집/집계 로직은 변경하지 않는다. API가 제공하는 기간 정보로 표현을 바꾸는 경우 데이터 계약을 먼저 확인한다. 네이버 지도 인증 문제는 조사·수정하지 않는다. 학교 탭 전환 후 로드 오류는 원인이 미확정된 별도 관찰 사항으로 기록한다. 확정된 로고를 임의 변경하지 않는다.

검증 폭360/390/430/768/1280, 글자200% 확대, 키보드 탐색, 포커스, 긴 이름/가격, 모든 상태, 차트 경계, 탭 활성, 44px 터치, 색 대비. 글자가 잘리거나 페이지 전체가 가로로 넘치면 미완료. 표 내부 가로 스크롤은 허용한다. DOM/computed style로 역할별 값 일치 확인. 스크린샷·화면 녹화 생성 금지. 필요한 기존 타입 검사/린트/빌드만 실행하고 무관한 테스트 확대를 하지 않는다.

적용 순서: 토큰 및 기준 컴포넌트 → 관리비/계산기/거래행 → 시세/비교/생활 → 다른 페이지의 동일 역할 확장. 전역 컴포넌트 변경 시 주요 페이지 영향 확인. Production 배포와 병합은 별도 요청 전까지 하지 않는다.

완료 보고는 복사 가능한 단일 코드블록: 적용 범위, 구 정책 제거 범위, 최종 토큰, 검증 결과, 미검증/잔여 오류. 마지막 줄에 Preview 링크만 코드블록 밖 표시. 실제 검증하지 않은 항목은 완료라고 보고하지 않는다.


## 10. 모바일 우선 적용 기준 — 사용자 피드백 반영

PC 실측만으로 모바일 완료 판정을 내리지 않는다. 현재 근거는 제공된 iPhone 캡처 8장에 대한 시각 검토다. 360/390/430 CSS px의 실제 브라우저 렌더링, 모바일 computed style, 터치 동작은 미검증이다. 현재 연결 브라우저의 공개 조작 API에는 뷰포트 변경 기능이 없어 이 세 크기의 실측을 완료했다고 주장하지 않는다. 캡처 픽셀을 CSS px로 단순 환산하지 않는다.

### 캡처에서 확인한 현상

- 시세 4열 요약에서 최고가 대비 설명이 여러 줄로 꺾인다. 제목·기간 버튼이 같은 줄을 차지한다.
- 거래행 왼쪽에 날짜와 층/면적/거래유형, 오른쪽에 금액이 있다. 2줄 구조는 유지할 가치가 있다.
- 계산기 입력값과 한글 환산 금액이 같은 입력 영역의 좌우를 점유한다.
- 가격 비교는 지역명·막대·단위 포함 금액이 한 행에 있어 좁은 폭에서 경쟁한다.
- 주변 단지 비교는 라벨 1열+단지 3열이다. 열을 유지하려고 글자를 줄이는 방식은 피해야 한다.
- 생활시설 3×3 배열과 여러 차트가 누적되어 스크롤 길이가 길다.
- 주변 공급의 유형·동·세대수·면적 배지가 한 줄에 몰린다.
- 관리비는 반복 숫자가 강하다. 평균 기준과 구성 항목의 위계 분리가 필요하다.

### 모바일 배치 결정

버튼 터치 영역 확대는 보이지 않는 영역을 서로 겹쳐 구현하지 않는다. 겹침 없이44px 영역을 확보하며 필요하면 줄 배치를 바꾼다. 단순 정보행에는 일괄44px 최소 높이를 강요하지 않고 행간과10~12px 상하 여백을 사용한다. 클릭 가능한 행에44px를 적용한다. 이 규칙은 앞의 일반 정보행 min-height44 기준을 대체한다.

### 모바일 완료 조건

360/390/430px 각각에서 실제 렌더링과 computed style을 확인할 것. 390px를 기본 설계 폭으로, 360px를 최소 폭으로, 430px를 넓은 모바일로 검사한다. 금액·단위 잘림, 제목/탭 충돌, 툴팁 화면 이탈, 전체 페이지 가로스크롤이 없어야 한다. iOS Safari의 입력 포커스와 하단 안전영역, Android Chrome의 줄바꿈은 별도로 점검한다. 모바일 실기기에서 확인하지 못했다면 데스크톱 에뮬레이션 결과와 구분해서 보고한다.

## 11. 랩시리즈 공통 선택 UI (segmented family)

탭·분류·기간 필터는 **하나의 segmented control 계열**을 쓴다. 위계는 형태가 아니라 **크기·배치·콘텐츠 범위**로만 나눈다.

기존 1차 독립 버튼형·폴더형(콘텐츠 연결 밑줄형)·진한 청록 채움형·단순 밑줄형은 폐기한다.

공통 문법:
- 연회색 트랙 `#F1F5F9` + 트랙 안 흰 선택 면 `#FFFFFF`
- 선택 글자 `#0F766E`, 비선택 글자 `#64748B`
- 트랙 radius 8px, 선택 면 radius 6px, 트랙 padding 3px
- 선택 면 그림자 `0 1px 2px rgba(15, 23, 42, 0.08)` (최소 깊이만)
- 동일 폭 기본, 활성 시 글자 크기·항목 폭·전체 높이 불변
- 선택 면 이동 160ms, `prefers-reduced-motion` 시 제거
- 금지: 그라데이션, 진한 청록 채움, 밑줄형, 개별 버튼 테두리, 청록 선택 테두리

### 1차 — primary (48px)

- 적용: 매수비용 / 보유세 / 대출 등 주요 모드
- 높이 48px, 글자 16/24, 선택 600 / 비선택 500, 콘텐츠 영역 전체 폭
- 제목·설명 아래 16px, 선택기 아래 첫 콘텐츠까지 24px
- 카드 좌우 콘텐츠 padding 안에 배치 (full-bleed·폴더형 금지)

### 2차 — secondary (40px)

- 적용: 매매/전월세, 가격 수준/변동률, 주변 생활 내부 분류 등
- 높이 40px, 글자 14/20, 선택 600 / 비선택 500
- 섹션 전체 또는 레이아웃에 맞는 적정 폭

### 3차 — compact (30px visual)

- 적용: 시세 1년/3년/5년/전체 등 기간·조건 preset
- 보이는 높이 30px, 글자 13/20, 선택 600 / 비선택 500, 내용 너비
- 시세 추이 제목 오른쪽 우선, 충돌 시 다음 행 우측 (글자 축소 금지)
- 실제 터치 영역 항목별 44×44 이상, 숨은 영역 겹침 금지
- preset과 슬라이더 양방향 연동. 임의 기간이 preset과 불일치하면 활성 표시 해제

### 접근성

- 색과 선택 면 형태로 상태 표시
- 콘텐츠 패널 전환: tablist / tab / tabpanel (+ aria-controls)
- 조건 선택: radiogroup / radio
- 방향키·Enter/Space, focus-visible 2px 청록 outline offset 2px
- 글자 200% 확대 시 높이 증가 허용. 모바일 묶음 약 5개 이하 우선
- 360px에서 넘치면 해당 컨트롤만 가로 스크롤 또는 기존 드롭다운 (페이지 가로 스크롤 금지)

### 구현

- `LabTabs` variant=`primary` | `secondary` | `compact` (`src/components/ui/LabTabs.tsx`)
- 공통 트랙 + `.lab-tabs__thumb` 슬라이딩 선택 면 (`src/app/globals.css`)
- 색·radius·그림자는 `--lab-*` / `--lab-tabs-*` 토큰에서 관리 (페이지별 하드코딩 금지)
- SSR/hydration 시 첫 측정 후에만 thumb transition 활성화
